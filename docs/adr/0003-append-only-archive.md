# ADR-0003：周期归档只追加、不可改写，差异只能说明追加

- 状态：已采纳（2026-10-04）
- 前置决策：[ADR-0001](0001-natural-day-period.md)、[ADR-0002](0002-attribution-by-start-time.md)

## 背景

自然日滚动时上一周期的累计量要归档。问题是归档之后：

1. 跨零点那一拍在零点后才完成计量，能量按开始时刻归属（ADR-0002）
   应属于昨天，但昨天已经冻结；
2. 电表补传、采集链路延迟会带来更晚到达的归属昨日数据；
3. 与电表/电网对账发现差额时，存在"重算历史账单"的诱惑——一旦允许
   重算，月报出了又改、审计链路失去可信基准。

## 决策

1. **滚动即冻结**：跨过零点时把上一自然日的累计量（充放电量、峰谷
   分档桶、拒绝次数）冻结成不可变快照（`DayArchive`），当日累计清零。
   时钟跳过的中间闲置日以零值快照归档，保证月结日序列连续。
2. **迟到数据只追加**：冻结之后到达的、归属该日的分片，追加为
   `LateSlice`（带来源与到达时刻）；日有效合计 = 冻结值 + 追加分片，
   冻结快照本身永远不变。
3. **差异只能说明**：与外部对账数据有出入时，追加一条 `DiffNote`
   （记录我方值、对方值、差额、来源、原因、时刻），不改正任何历史
   数值，也不把差额静默计入月结金额；月结报告把差异说明**列示但
   不入账**。
4. **拒绝不回滚**：额度用满的拒绝发生在任何下发与记账之前，只累计
   拒绝计数、保持上一个有效功率，没有已记账数据需要回滚；事后实测
   若发现超配额（计量误差累积），已入账分片同样不回滚，只置
   `over_quota` 告警，下一拍事前预检拒绝。
5. **月结复算两条路径交叉校验**：月结金额既按日冻结桶直接汇总，也
   从"冻结桶 + 迟到分片"重建分片流再结算一次；两条路径不一致直接
   报错，防止归档/月结代码各自漂移。

## 被否方案

- **允许重算并覆盖历史归档**：方便，但月报、发票、审计报告一旦出具
  就可能被悄悄改写，等于没有账；否决。
- **迟到数据并入当日**：实现最简单，但跨零点能量"在配额上属昨天、
  在台账上属今天"，正是用户反映的对不上账；否决。
- **差额直接调账**：没有留痕，事后无法解释月结数字为何变化；差异
  必须以带原因和来源的说明记录。

## 后果

- 归档记录可长期作为审计基准；任何历史变动都以追加记录留痕。
- 月结 = Σ 日冻结 + Σ 迟到分片，附差异说明清单；金额可逐笔追溯到
  能量分片。
- 控制台提供只读对账视图 `/api/quota/reconciliation`、月结视图
  `/api/quota/monthly` 和差异说明入口 `POST /api/quota/diff-note`。
